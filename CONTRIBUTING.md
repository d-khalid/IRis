# Contributing

This project facilitates contributors but requires strict guidelines to be followed to avoid low quality contributions. Have a read bellow to see what's in (^_^)

---

## Use of AI Agents

We would like to declare that this codebase is entirely organic and pest-free (manually typed). Absolutely no AI-Agents have worked on this codebase ever. That is, they haven't made edits in it directly.

The `AGENTS.md` file is there to facilitate the use of AI-agents in **Ask Mode** to query about better approaches, more efficient code, tracing down logic in some places, etc. We believe this is how AI-agents should be used in programming, because only software engineers are smart enough to be making architectural decisions. 

Decisions that involve trade-offs, deciding whether something is worth adding or removing, making the experience more seemless for a human, user-experience engineering, (and so on) none of these can ever be done by AI-agents.

The file instructs agents to use the least number of tokens, avoid markdown language, try to sound like a human and about how [Code is Formatted](#code-formatting). Have a look [here]()

## Issue/PR Templates

These keep every issue/PR in structure and serve as guidance.
But do keep in mind that these are not hardcoded rules to blindly follow.
It is perfectly fine to backspace the template structure and draft your issue/PR in a blank one.

---

## Becoming a Contributor

This is the most important part. We put it here but this is the entry point for contributors. Follow these:

- Pick any issue from the issues section. Documentation-related changes are not accepted from contributors because they are low-effort.
- Comment in the issue, discuss the solution, and get it approved by a maintainer. Only then you should be working on an issue.
- You do not need to type in long PRs. Since you've already discussed on the topic just link the issue number and it will be accepted.
- Any signs of Agentic Coding in the PR/issue/changes will be considered a violation of the above rules and the PR will not be accepted.

We are absolutely not allowing huge numbers of contributors bloating this repository. So just keep in mind these policies are for everyone who wants to contribute.
